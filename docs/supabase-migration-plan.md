| ชีต | แถว | ขนาด JSON | เวลาตอบ | ใครใช้ |

**ปัญหาที่วัดได้**

- ยิง `?action=config` 4 เส้นพร้อมกัน → **30.8 วินาที และพัง 3 ใน 4** (ตอบเป็นหน้า HTML error)
- แม้ cache hit ก็ยัง **1.7 วินาที** — เป็นพื้นของ Apps Script เอง แก้โค้ดไม่ลง
- `getConfig()` เรียก `readConfig_` 6 รอบ **แต่ละรอบอ่านชีตทั้งใบ**
- ไม่มี query/filter/pagination ฝั่งเซิร์ฟเวอร์ — โยน JSON ทั้งก้อนให้เบราว์เซอร์กรองเอง
- `LockService` ทำให้เขียนพร้อมกันไม่ได้ ต้องต่อคิว

**เป้าหมาย** — เวลาตอบระดับ 0.1-0.3 วินาที · ไม่มี request พังจากการยิงพร้อมกัน · กรอง/แบ่งหน้าฝั่งเซิร์ฟเวอร์ได้

## หลักการที่ใช้ทุกเฟส

1. **เขียนคู่ (dual-write)** — ช่วงเปลี่ยนผ่านเขียนทั้ง Supabase และ Sheets · Sheets ยังมีข้อมูลครบตลอด
2. **อ่าน Supabase ก่อน ถอย Sheets อัตโนมัติ** — Supabase ล่ม/ยังไม่ตั้งค่า ระบบทำงานต่อได้เหมือนเดิม
3. **ปิดไว้จนกว่าจะพร้อม** — ไม่ใส่ URL/key = ไม่มีอะไรเปลี่ยน
4. **ย้อนกลับได้ตลอด** — กดปุ่มเดียวกลับไปใช้ Sheets
5. **วัดก่อน-หลังทุกเฟส** — ไม่เดาว่าเร็วขึ้น

## ⚠️ ความปลอดภัย — ต้องตัดสินใจก่อนเฟส 5

ตอนนี้ RLS ตั้งให้ `anon` อ่าน-เขียนได้ทั้งหมด = **ระดับเดียวกับ Apps Script ที่ตั้ง "Anyone" อยู่ตอนนี้** — ย้ายแล้วไม่ได้แย่ลง แต่ก็ไม่ได้ปลอดภัยขึ้น

ใครได้ anon key (อยู่ในหน้าเว็บ ใครเปิด DevTools ก็เห็น) อ่าน-แก้ข้อมูลได้หมด

**ทางเลือก** — ทำ Supabase Auth จริง แล้วล็อก policy ตาม role (admin/BZM/สาขา) · เป็นงานแยกต่างหาก ไม่รวมในแผนนี้
